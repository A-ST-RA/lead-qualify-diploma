**С подкреплением** - агент учится принимать оптимальные решения, взаимодействуя со средой методом проб и ошибок

## Модуль 5. Оценка качества

Accuracy - (TP + TN) / (TP + TN + FP + FN)

TP - Правильно позитивные

TN - Правильно негативные

FP - Ложно позитивные

FN - Ложно негативные

Precision = TP / (TP + FP) (точность ответов)

Recall - TP / (TP + FN) (полнота захвата)

macro avg:
"как модель работает по среднему классу, если каждый класс одинаково важен"

weighted avg:
"как модель работает по среднему объекту, учитывая, что одних классов больше"

### F1

F1 = 2 _ (precision _ recall) / (precision + recall)

F1 - метрика оценки качества моделей классификации, которая представляет собой среднее гармоническое между точностью (Precision) и полнотой (Recall)

### ROC-AUC

ROC-AUC показывает, насколько хорошо модель ранжирует объекты:
дает ли она хорошим лидам score выше, чем плохим

## Модуль 6. feature engineering

Тут я разбираюсь с тем, как отбирать и улучшать признаки для модели

Например, у нас есть данные вида:

```text
source = "google_ads"
industry = "education"
requested_budget = пусто
time_on_site_sec = 420
viewed_pricing = true
last_visit_date = "2026-04-20"
```

И нам их нужно преобразовать во что-то типа:

```text
source_google_ads = 1
industry_education = 1
requested_budget = 75000
time_on_site_sec_scaled = ...
viewed_pricing = 1
days_since_last_visit = 6
```

### Как этого добиться

#### One-hot

Разбиваем field = [a, b, c] на is_a, is_b, is_c

**Где применяется?** - там где нам нужно понять, есть ли такой признак, но его вид нам не нужен

#### Ordnial

Преобразовываем field = [a, b, c] в = [1, 2, 3]

**Где применяется?** - там, где важно изменение (температура, крутость подписки)

### Заполнение пустых данных

Тут стоит смотреть, почему они не долетели и как с этим работать

Если кратко, можно засунуть медианное значние и указать, что не было заполнено, если булево, то можно по умолчанию поставить 0 или поставить некий "unknown"

### Сглаживание больших значений

Если даже признак слишком большой, то все равно, итоговый резльутат будет приведен к типу
(value - train_mean) / train_std
Train_mean - среднее арифмтическое всех значнией, train_std - стандартно значение, буквально считается, на сколько раз оно превышает/пренижает значение

### Как это делать

В sklearn есть объекты трансформеры, так же можно объеденять их в pipline, что-бы потом
и на тренировке модели и в реальных данных использовать этот пайплайн и не потерять данные

## Модуль 7. Более продвинутые модельки

Есть разные модельки, мы уже посмотрели LogisticRegression и RandomForest

### DecisionTree

DecisionTree(дерево решений) -> Это дерево, которое строит разные ветвления на выборке

#### Плюсы модели

1. Простая
2. Контролируемая

#### Минусы модели

1. Легко переобучается, потому что может делать слишком глубокие деревья на train data

**Например**
```text
if requested_budget > 83217
and page_views_count <= 11
and company_size == 7
and downloaded_pdf == 1
then deal_won = 1
```

Что-бы этого избежать, модели добавляют такие параметры как:

```py
max_depth # Максимальная глубина дерева
min_samples_leaf # Минимальное количество объектов в этом листе
min_samples_split # минимум объектов, чтобы узел можно было делить дальше
```

### GradientBoosting

Еще одна разновидность деревьев, которая строит деревья последовательно, корректируя результаты прошлых деревьев

### Разбиние датасета на куски

Это нужно для того, что-бы обучить одну и ту де модель 5 раз на дазныхз кусках данных

StratifiedKFold - Разрезает датасет на разные куски, например, n_splits=5 сделает 5 мини датасетов

Обучение после этого происходит так:

```text
run 1: train = fold2+fold3+fold4+fold5, test = fold1
run 2: train = fold1+fold3+fold4+fold5, test = fold2
run 3: train = fold1+fold2+fold4+fold5, test = fold3
run 4: train = fold1+fold2+fold3+fold5, test = fold4
run 5: train = fold1+fold2+fold3+fold4, test = fold5
```

Потом метрики усредняются.

То есть каждая строка один раз побывает в test, а несколько раз в train.

Cross-validation используется для сравнения моделей и выбора лучшей конфигурации.
После выбора лучшая модель заново обучается на обучающей выборке и сохраняется вместе с preprocessing pipeline.

### Резюме 7 модуля:

DecisionTree не лучший основной кандидат, потому что одно глубокое дерево легко подстраивается под обучающие данные и переобучается.

RandomForest хороший кандидат, потому что это ансамбль разных деревьев. Он усредняет их ответы, поэтому обычно стабильнее одного дерева и хорошо работает на табличных данных.

HistGradientBoosting может быть сильнее, потому что строит деревья последовательно: каждое следующее дерево исправляет ошибки текущей модели.

Boosting может переобучиться, если:

слишком много деревьев
слишком высокая learning_rate
слишком сложные деревья
слишком маленький min_samples_leaf
мало данных или много шума

## Модуль 8. Интерпретация модели

модель должна не только выдать score, но и объяснить, **почему лид получил высокий или низкий балл.**

### Feature Importance

У RandomForest есть:

```py
forest_model.feature_importances_
```

Это показывает, какие признаки модель чаще и сильнее использовала для разбиений.

Пример:

```
requested_budget      0.32
time_on_site_sec      0.21
viewed_pricing        0.18
company_size          0.12
source_google_ads     0.05
```
